# GuitarPal 账号与同步方案

## 产品原则

GuitarPal 继续采用 local-first：不登录也能使用当前全部功能，账号只用于跨设备同步、备份和未来的协作能力。不能因为网络或账号服务不可用而阻塞练习、播放、录音或记录。

登录首版建议支持邮箱一次性链接/验证码与 Google 登录；iOS 开发时补充 Apple 登录。应用不自行收集或保存密码，第三方登录使用 OAuth 2.1 / OpenID Connect 与 PKCE，并通过系统浏览器完成授权。

## 客户端边界

认证层先抽象为 `AuthRepository`，向 UI 暴露统一的会话状态：

- `local`：未登录，本机数据可完整使用；
- `authenticating`：正在系统浏览器中授权；
- `signedIn`：持有后端签发的稳定用户 ID；
- `expired`：会话需要重新认证，但本机数据仍可读写。

短期访问令牌只保存在内存，刷新凭据写入 Android Keystore / iOS Keychain。业务表不直接依赖 Google、Apple 或邮箱地址，而只关联后端稳定的 `userId`，避免用户更换登录方式时丢失数据。

客户端的授权请求层已经按照 [RFC 7636](https://www.rfc-editor.org/rfc/rfc7636) 实现 PKCE S256：每次授权独立生成 `code_verifier`、`state` 和 OpenID Connect `nonce`，只接受与预期回调地址和 `state` 完全一致的结果。授权端点、令牌端点、客户端 ID、回调地址、scope 和可用登录方式集中在 `AuthConfiguration` 校验，页面不会直接依赖某个认证供应商。

## 首次登录与本地数据迁移

首次登录不覆盖本机数据库。客户端先创建一份迁移预览，展示本机与云端的曲目、片段、计划、练习记录、笔记和录音数量，再由用户确认“合并到账号”。

所有可同步记录需要补充以下同步字段：

- 稳定的客户端 UUID；
- `ownerId`（本地模式为空）；
- `revision` 或服务端版本；
- `updatedAt`；
- `deletedAt` 墓碑，防止另一台设备恢复已删除数据。

客户端用 outbox 记录待上传变更。服务器确认后再推进同步游标。短暂断网时继续写本机数据库，恢复网络后增量上传。

冲突策略：练习记录和录音元数据尽量追加而非覆盖；计划、片段、笔记采用字段级或“最后修改优先”，发生不可安全合并的冲突时保留两个版本并让用户选择。

## 同步范围与录音隐私

第一阶段只同步体积小、恢复价值高的数据：来源元数据、片段、计划、练习记录、笔记和应用偏好。外部平台链接只同步 URL 和用户编辑的元数据，不同步受版权保护的视频文件。

录音文件属于敏感内容，第二阶段单独实现：

- 默认仅保存在本机；
- 用户主动开启“同步录音”后才上传；
- 文件进入私有对象存储，通过短期签名 URL 上传和播放；
- 服务端数据库仅保存所有者、校验值、时长和存储键；
- 支持单条删除、批量导出、停止同步和账号注销后的彻底删除。

后端必须对每张业务表执行行级所有权校验，不能依赖客户端传来的 `userId`。日志和分析事件不记录令牌、原始录音或完整私人笔记。

## 分阶段交付

1. **客户端准备（已完成）**：账号页已接入供应商无关的 `AuthRepository`/`AccountSession`；无 Supabase 构建配置时由本地模式实现提供状态，配置后切换为 Supabase 实现。页面会实时汇总曲目、片段、计划、练习记录、录音和笔记数量，作为未来首次合并的迁移预览。现有业务不依赖登录。
2. **认证协议准备（已完成）**：已实现登录方式可用性、邮箱输入入口、PKCE S256 授权请求、回调地址与 `state` 校验，以及供应商身份到应用会话的转换边界。未配置的方式不会显示成可用，也不会发起伪登录。
3. **认证闭环（进行中）**：已选定 Supabase，并完成 Flutter SDK 初始化、邮箱 Magic Link、Google OAuth 调用、Android Deep Link、PKCE 回调恢复、平台安全存储、会话监听和退出登录。邮箱 Provider 已启用，`com.guitarpal.app://login-callback/` 已加入 Supabase 回调允许列表；下一步进行真机邮件回跳闭环测试。Google 仍需在 Google Auth Platform 与 Supabase Dashboard 配置 Client ID/Secret 后开启构建开关。账号删除入口尚未实现。
4. **元数据同步（进行中）**：本机 Drift outbox 已完成，覆盖曲目、片段、计划和练习记录，并支持旧数据回填、同实体变更合并、失败状态及基于修订号的安全确认；账号页已展示待同步数量。下一步创建 Supabase 服务端表与 RLS，完成首次合并确认、批量上传、删除墓碑、增量拉取、冲突处理和同步游标。
5. **可选录音同步**：私有对象存储、Wi-Fi/充电策略、容量提示、导出和彻底删除。

Supabase 的本地构建参数、Redirect URL、Google Provider 和后续 CLI 配置见 [Supabase 配置](supabase_setup.md)。进入元数据同步前仍需确定隐私政策、服务区域、配额与成本；客户端页面继续只依赖供应商无关的接口，避免把业务流和本地数据库绑死在 Supabase SDK 上。
