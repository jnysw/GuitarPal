# 和弦自动对齐与人工微调

2026-11-01。新服务端实现见 [服务端 Draft PR](https://github.com/jnysw/chordengine-algorithm-server/pull/1)，Windows 操作见 [更新说明](CHORD_TIMELINE_UPDATE.md)。本机目前未验证私网服务已部署，不能把客户端／CPU 测试称为 Windows 线上质量验收。

## 坐标协议

v1 `segments.start/end` 仍是裁剪后音频秒数。服务端保留 librosa 实际返回的 trim 起始索引，新任务增量返回：

```json
{"timeline":{"version":1,"coordinate_system":"trimmed_input_seconds","sample_rate_hz":22050,"input_sample_count":220500,"analysis_start_sample":22050,"analysis_sample_count":176400,"frame_hop_samples":2048}}
```

这是协议示例：输入 10 秒、分析覆盖 1–9 秒。客户端把 `分析结果秒数 + 实际裁剪起点 + 本地提取区间起点` 映射为原视频时间；不乘除播放倍速，也不按时长比例拉伸。前导静音／分析覆盖之外显示未分析，不伪造无和弦。

服务端同时修复 BTC 帧数整除窗口时把 padding 算成整窗的问题，防止漏掉最后一窗；使用实际 detector feature hop 建立时间与限制拍点修正，尾部只按实际分析长度裁剪。默认 BTC 帧间隔约 93ms，坐标恢复不代表识别边界拥有毫秒级精度，更不代替真实歌曲质量基准。

## 客户端行为

- 合法采样映射且完整输入时长匹配当前提取区间时，正常页／全屏／滚动和弦／分析列表／舞台自动使用同一原视频时间，显示「自动对齐原音频」。
- 人工校准始终优先；「微调和弦时间」预填当前自动起点，用户可修改；「恢复自动对齐」清除人工覆盖，不改原始结果或上传文件。
- metadata 缺失、未知版本、非整数／越界采样、结果覆盖与采样长度不符、输入时长不匹配时不自动应用。兼容旧标签与已有人工校准，保留待校准提示；不猜静音偏移，不强制重新上传或分析。
- 旧结果没有原始 trim 索引，不能可靠追补。Windows 更新后，用户明确发起的新任务才有新映射。没有在 Mac 自动部署 Windows 或自动重跑旧用户媒体。

验证：前导静音、区间起点、精确边界、A-B 回跳、人工覆盖／恢复、取整时长及不可信 metadata 的 Dart 测试；真实安卓原视频测试在开头一秒不提前显示和弦，之后自动 C→Am，人工覆盖再恢复、滚动／指法／A-B／全屏与唯一计时一并通过。服务端用生成信号／真实 trim 和真实预测循环（假权重输出）验证，不作音乐识别准确率承诺。
