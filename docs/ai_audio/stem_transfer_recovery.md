# 分轨传输与缓存恢复

更新：2026-10-30。入口仍是本地视频练习页的「和弦与分轨」，使用原播放器、进度、倍速和 A-B。

## 使用行为

- 同一源文件、同一分析区间已有结果时，优先选择「使用已有结果」，补齐下载后载入混音。重新分析需要明确选择，不因下载错误自动重新上传。
- 下载最多同时进行两条音轨，显示全部音轨的已收字节、总量、完成数、平均传输速度和预计剩余时间。刚开始及速度不可估算时不显示倒计时。
- 「暂停下载，保留进度」停止网络传输；再次点击该结果的「在当前视频中使用分轨」继续。离开页面、进入录音或更换播放器也会停止旧下载，避免晚到结果接管新练习。
- 网络断开、超时或临时服务器错误最多自动尝试三次 **GET**。完整文件不重复下载；未完成文件在服务器支持条件续传时从断点继续。应用重启后仍保留进度。
- 上传、服务器排队／计算、音轨下载、本机解码分别显示。长区间的算法计算不会因客户端重试而加快；可先只分析需要练习的 A-B。已有服务器任务继续查询，不自动再建任务。

## 文件安全与兼容

`ResumableStemTransfer` 在应用私有目录逐块写入 `.part`，不再每个网络包都落盘 flush；接收完成统一提交。超时按网络无数据的时间计算，不限制正常持续传输的总时长。

临时清单记录文件身份与强 ETag（或 Last-Modified）。续传使用 Range + If-Range，核对 206 的区间、总长及返回版本。服务器返回完整 200 时替换该轨临时文件，不追加造成损坏；416 清除该轨断点后有限次重取。缺少可靠版本标记时不进行不安全的追加。暂停或失败不会把 `.part` 当成可播放文件。

发布完整缓存前校验实际字节数、容器、PCM16、采样率、声道和时长，并保存 SHA-256 收据。新进程复查文件与收据；仅修复失效的一轨。旧 WAV 没有收据时先检查格式，再建立收据。服务器未提供原始校验和，因此不能把客户端首次计算的哈希称为服务端端到端校验。

新任务请求服务已有的 `flac16` 输出，以无损压缩减少传输体积。Android 将已下载 FLAC 在本机解码为 PCM16 WAV 后交给现有混音引擎，保留可复用的解码缓存；解码失败保留下载文件，重试载入不要求重新下载。旧 PCM16 WAV 继续直接播放。首次解码会消耗本机时间与额外存储，压缩比例取决于音频内容，不能保证固定倍数。

删除任务会清理该任务的完整文件、续传片段、验证收据和本机解码副本；活动下载时拒绝删除。后台或录音期间不自动下载缺失文件，已保存的原声／混音选择继续沿用。

## 服务端速度待核对

当前仓库没有 Windows 实际运行的模型代码。健康响应没有 GPU 型号、CUDA 可用性、模型设备、精度或各阶段耗时，不能据此确认 RTX 5070 Ti 已参与推理。

下一步应在 Windows 服务记录：排队、解码、模型推理、编码分别耗时，实际模型／设备、CUDA 与驱动版本、GPU 利用率／显存峰值；使用相同音频长度、相同模型和配置作对照。先确认实际设备与瓶颈，再验证分块／批大小／精度等服务配置的质量与显存影响。客户端不猜测参数或静默改用低质量模型，不承诺长曲加速已经完成。
