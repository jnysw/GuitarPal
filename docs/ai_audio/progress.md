## 第六批：回归本地视频练习主流程

用户明确要求和弦／分轨结合本地导入练习。此前独立工具页与手动关联不是最终产品流程，本批改为同一视频页内完成，未新增一级导航。

- 移除个人中心独立音频入口，播放器右上角和页内提供「和弦与分轨」。直接从当前整段视频或 A-B 提取 PCM16 音频，确认后上传，来源及当前计划自动绑定，无需重复选文件或关联。
- Drift v13 保存提取区间、来源文件元信息、输入 WAV SHA-256、240 点波形及独立人工和弦偏移。旧 v12 结果和统计关联保留；无媒体映射的旧任务不参与视频定位，文件变化时拒用旧结果。
- 页内显示任务、波形定位及和弦结果。旧服务裁剪静音的偏移仍未知，需显式人工校准后才开放和弦视频定位／当前下一和弦；机器结果原样保留。
- 分轨直接载入同一视频原生视图，以共享音频时钟驱动画面，覆盖区间静音原声、区间外恢复；逐轨音量／静音／独奏共用原进度、倍速、A-B 和 recorder。进入全屏保留面板状态；录音开始切回原声。
- 修复播放至视频末尾时已启用 A-B 不再循环的问题；明确用户暂停仍保持暂停。没有创建第二条练习会话，也没有把旧手动统计关联冒充时间映射。
- 本批范围、测试及后续见 [视频练习工作区](video_practice_workspace.md)。同步目前为周期纠正，沿用视频 A-B 容差，不承诺逐样本音画一致；缩放时间轴、指法及真实长视频听感仍待下一批。
- 验证：静态分析无问题，完整 Flutter 测试 **313 项通过**；Android 新增视频分析／分轨集成 **2 项通过**，原视频画面、错误恢复、全屏进度回归 **3 项通过**。新增集成使用自生成 8 秒测试视频、真实原生 PCM 提取／播放及算法响应替身，不重发模型推理、不改动用户数据库。全屏测试等待系统真实切换状态，画面测试暂停保留首帧后检查像素，避免短样本在截图前结束。

## 第五批：分轨统计与曲目/计划关联

- 分轨练习新增“关联曲目／计划”。关联只用于统计归档，不据此猜测视频时间轴。未关联时保留试听；可选择曲目统计或其整曲计划，暂不接片段计划。
- Drift v11 → v12 为算法任务增加可空曲目/计划关联。校验曲目存在、计划归属和非片段计划；删除元数据会清空关联，已保存的历史练习不随任务/下载删除。
- 复用既有 PracticePlaybackSessionRecorder / PracticeSessionRepository / 统计 outbox，只创建一条播放会话；音轨数、进度跳转和倍速不乘算有效练习时长。切换混音模式保留累计时间/循环，切换统计归属先完成旧会话。
- 每 5 秒播放检查点、暂停/后台保存、返回前完成会话。后台立即冻结，并在恢复时重新建立原生循环计数基线；过期回调不重启计时。正常退出写 completed=true，同一 ID 覆盖快照。
- 保存失败提供重试/保留检查点退出；修复共享 recorder 最终保存失败后不能重试的问题，重试保持同一会话 ID 与累计值。
- 全量 Flutter 测试 **309 项通过**，静态分析无问题。本批 Android 统计端到端和原生混音回归 **3 项通过**；联网任务测试按配置跳过，未重跑算法。已验证实际 PCM 播放→循环→模式切换→返回→仅一条记录→整曲计划完成；新增测试使用隔离内存数据库和合成音频，不改动用户数据库或请求模型。

## 第四批：离线分轨练习

- 从结果页进入“分轨练习”，仅使用已下载的音轨；支持六轨混音或人声＋派生伴奏两种互斥模式，防止伴奏重复叠加。
- 使用单个 Android AudioTrack 输出，把不同音轨的相同 PCM 帧一起混合。统一媒体位置、seek、暂停/恢复和 0.50–2.00x / 0.01 步进；复用既有数字输入、滑动、按键和预设倍速控件。
- 逐轨音量/静音/独奏、主音量；仅已载入音轨参与独奏判定。线性求和后作用主音量与限幅，静音/独奏不额外放大其他轨。支持下载部分音轨先练习。
- 原生按帧组装 A-B 循环，UI 定时器只显示时钟，不负责回跳；支持当前位置设点、输入毫秒时间、循环计数。修复变速播放到短尾部的缓冲排空问题。
- “保存练习设置”将模式、音量/开关、倍速和启用中的 A-B 存到任务私有 JSON，下次离线恢复；删除任务一并清理。未增加数据库迁移（仍 v11）。
- 输入限定相同采样率/声道/时长的 PCM16 WAV，逐块读取；FLAC/float WAV 的原有下载/试听入口保留，解码能力以设备为准，不冒充可混音。离开分轨练习释放输出，后台/音频焦点丢失暂停。
- 本页暂不写练习统计，未与视频原曲或录音比较页共享会话。原曲时间映射/媒体修订、统一统计/视频静音、真机耳机/电话/延迟和听感仍待验收，不宣称整个 M4 完成。
- 实现说明与可复现测试见 [分轨练习](stem_mix_practice.md)。第三批与更早章节保留其当时验收状态。
- 本批验证：`flutter analyze` 无问题；完整 Flutter 测试 **304 项通过**；两个 Android 集成文件合计 **5 项通过**，包含实际 Windows 六轨/人声伴奏回听与原试听回归。正常 Debug APK 使用被忽略的本机配置构建。未创建付费资源，未重新提交模型推理任务。

## 第二批：Windows v1 客户端与实验任务页

- `我的 → 音频工具（实验）`，路由 `/audio-tools`，仅 Debug 构建可使用；Release 不开放无鉴权实验服务。
- 可手动填写服务地址，或使用 `ALGORITHM_BASE_URL` 构建参数；HTTP 仅允许调试版的私有/回环地址。URL 中不接受内嵌密码，响应链接不得跨源或替换任务路径。
- Android 系统音频选择器创建有上限的私有副本；支持 MP3/WAV/FLAC/OGG/M4A，2–600 秒且不超过 50 MiB。已有练习录音可直接选取，移除分析历史不会删除原录音。
- 明确确认接收服务器与文件大小后，以 multipart `audio` 上传，`hmm`/`include_raw_chords` 在 query，设备保留服务端默认。进度来自实际读取的上传字节，不伪造模型进度。
- 202 后保存任务 ID；页面前台每 2 秒顺序轮询，网络错误退避到 30 秒并尊重 `Retry-After`；重入继续查询。404/410 显示已失效，HTTP 200 的 failed 正确停止。
- POST 回执丢失/应用中断保留“接收状态未知”，不自动重传；移除历史只清理本机记录/导入副本，不声称取消服务器任务。
- JSON 结果本地落盘；旧 v1 时间轴明确标为裁剪后坐标，置信度始终不可用，不显示未可靠验证的 BPM，不猜原曲 offset 或开放错误的 A-B。
- 分轨数据类型/安全 URL 解析已预备，`instrumental` 保留 derived 语义；HTTP 服务、下载和同步尚未实现，UI 仍未开放分轨。
- 数据库 v9 → v10 新增 `AlgorithmTasks`，未改动来源/片段/计划/录音旧表；任务不进入元数据同步队列。

交接协议保存在 `contracts/legacy_algorithm/`，与未来 GuitarPal 生产 `/v1` 隔离。操作步骤和本轮限制见 [客户端联调说明](windows_client_setup.md)。

本批验证：`flutter analyze` 无问题；完整 Flutter 测试 **292 项通过**，含 loopback 真实 multipart HTTP 流程、页面上传确认→离线结果、响应丢失不重传、GET 退避/过期、晚到响应不恢复已删历史，以及 v9 → v10 旧数据保留。Android Debug APK 构建通过。真实 Windows 模型和 Android 系统选择器端到端联调尚未执行，按用户要求留待后续。

## 时间轴与数据约定

- 上传的是选好区间的音频，服务端不重复裁切；`source_offset_ms` 只在引擎相对坐标转原媒体坐标时加一次。
- 下发的 `segments` 已是 `source_media_ms`，App 直接以播放器媒体位置查询，不乘除倍速、不再次加 offset。
- `[start_ms,end_ms)`；间隙、N、X 和区间外语义不同，不能延续上一和弦。v1 禁用首尾静音裁剪。
- 缺真实置信度聚合方法时 `confidence=null`；调性/BPM 缺失也为 null。
- `model_manifest.json` 的两个候选 profile 关闭；fixtures 仅为测试数据。
