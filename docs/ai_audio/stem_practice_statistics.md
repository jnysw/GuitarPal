# 分轨练习统计与归档

更新：2026-10-28。

## 使用方式

进入分轨练习后，点击“关联曲目／计划”，先选择音频对应的练习库曲目，再选择“仅记入曲目练习”或该曲目的整曲计划。未关联时仍可试听，但不生成练习历史；关联后只记录之后的播放，不补算此前试听。

顶部显示统计归属及本次有效时长/循环。关联曲目后会进入既有个人反馈；关联整曲计划后，按既有计划日期和目标规则累计进度。片段计划涉及原曲位置对应，当前不提供，避免把任意分轨区间算作指定片段已练。

更改或解除关联会先暂停并完成旧会话。既有记录保留，新归属仅作用于后续播放。关联不会创建新曲目、改变已有来源，或宣称已经验证音频与视频时间轴匹配。

## 计时和保存

- 每个打开的分轨练习/统计归属使用一个 recorder 和稳定 UUID，会话只保存一次累计值，多轨混音不按轨数重复计时。
- 以实际播放状态下的墙钟时间计时，进度 seek、倍速和循环回跳不直接增加时长；载入音轨和切换模式的等待、暂停及后台不计入。沿用原视频播放器的不足 1 秒且无完成循环不落盘规则。
- 原生循环计数重建时保持本会话累计；后台会立即冻结计时并重建下一次计数基线，不把漏收的后台计数补入。过期异步播放快照按修订号丢弃。
- 播放中每 5 秒写恢复检查点（completed=false）；暂停、切换模式和后台也保存。返回时先暂停、取最后快照并完成会话（completed=true），再退出。
- 同一 ID 的 upsert 和 outbox 更新，旧检查点不能覆盖已完成结果。最终写失败可重试相同会话，不创建新 UUID；用户也可选择保留此前检查点直接退出。被操作系统终止仍可能丢失最后未保存的几秒。
- 统计沿用现有按会话开始日期归档的口径，跨午夜拆分尚未实现。播放状态以约 100ms 的原生快照观察，未声明逐样本的计时精度。

## 数据

Drift v12 在 AlgorithmTasks 增加 linkedSourceId / linkedPlanId 两个可空外键；旧任务默认不关联，不伪造历史。v10 同时补 operation，v9 及更早版本新建完整任务表。

关联变更事务中核对曲目存在、计划属于同曲目且 segmentId=null。曲目/计划删除会通过 SET NULL 清空关联；历史 PracticeSession 保留既有数据规则。任务、原音频副本、下载和设置删除均不删除已保存的练习统计。

会话复用现有仓库和本机同步 outbox。尚未实现的云端上传不会因本次接入而被称为已完成；原始音轨仍不进入元数据同步。

## 验证

Flutter 测试覆盖未关联/关联、原计数基线、模式计数重建、加载和暂停时间排除、后台及过期快照、一个稳定 ID、相同 outbox 实体、删除关联不删历史、非法/片段/跨曲目计划、v11/v10 升级，以及失败最终保存可重试。

Android `integration_test/stem_practice_statistics_test.dart` 使用真实 AudioTrack 混音和内存 SQLite：两轨播放/A-B、切换模式、暂停等待、退出后仅一条 finalized 会话，整曲计划进度可完成。音频为合成测试 WAV，测试结束清理自己的文件，不访问用户数据库。

本批不处理视频画面、录音比较、来源修订和片段时间映射。统计关联不能被后续代码直接当作可用于原曲定位的时间映射。
