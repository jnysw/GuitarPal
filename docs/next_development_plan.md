# GuitarPal 优化计划

更新于 2026-11-08。当前面向 Android 内测，优先改善本地视频从导入、分析到伴奏演奏的连续体验。详细历史见 [AI 音频进度](ai_audio/progress.md) 与 [演奏空间进度](performance_space/progress.md)。

## 已完成

- **练习工作区**支持 0.01 倍速、A-B 循环、片段和笔记。和弦带随原视频播放滚动，使用采样时间映射，并保留手动微调。分轨可按需下载、续传、离线混音和恢复上次选轨。
- **边练边分析**在打开分析确认、提交或下载期间保持当前播放。分轨下载暂停后可继续同一选轨。下载完成时如果视频仍在播放，留待用户点击载入音轨。
- **公网访客分析**已部署并通过 Android 实测。从本地视频练习页开始和弦分析或分轨，应用自动建立设备会话。模拟器用合成视频通过了真实双算法、下载续传与本机播放。开始查询时，分析面板优先处理最久未查询且已到查询时间的任务，退避中的任务不占当轮名额。[公网接入与验证](ai_audio/melpal_public_access.md)
- **演奏空间**可沿用本机分轨伴奏，音响动效跟随伴奏 PCM 电平。舞台录音、草稿恢复、同曲 A/B 回听与计划成果关联已接。数字作品首版支持 1.00× 伴奏混音和单独麦克风 WAV 导出。[导出说明](performance_space/digital_export_plan.md)

## 接下来按顺序推进

| 优先级 | 工作 | 交付与验收 |
| --- | --- | --- |
| P0 | 实体 Android 访客验收 | 用最新 APK 从「新建 → 本地视频 → 练习」分别完成扒和弦、分轨、选轨混音。覆盖空会话首次分析、重开后续查、切网／断网续传、服务忙时提示和离线使用已有缓存。每次确认只提交一次。覆盖 Wi-Fi 和移动网络，记录响应错误与恢复路径。 |
| P1 | 长曲分轨与下载 | Android 已采集 30 秒、3 分钟、8 分钟合成基线，覆盖真实服务、七轨下载、续传和本机载入。[实测记录](ai_audio/long_separation_baseline.md) 下一轮测提取吞吐和峰值内存，评估保留时间轴的无损压缩上传。用实体机和真实授权曲目补两类网络吞吐及恢复后的重传字节，服务端阶段耗时按可用诊断补齐。 |
| P1 | 非 1.00× 保音高导出 | 先评测 Android 本地时间伸缩，比较 0.75×、1.00×、1.25× 下的音高、输出时长、伴奏与录音起点及长曲峰值内存。通过确定性的参考音与真实乐器试听后开放非 1.00× 混音，验证取消、重试和失败时保留上次导出。 |
| P1 | 和弦与设备对齐 | 人工标注实际歌曲的和弦切换点，分别统计 A-B 片段和整曲的整体起点误差、切换误差及长段漂移。用实体手机的有线、USB、蓝牙回听路径测延迟，区分模型边界偏差和播放设备延迟，再决定是否加设备级校准。 |
| P2 | IP 舞台互动 | IP 素材到位后接入待机、倒计时、演奏、暂停和结束，验收缺素材回退、横竖屏、小屏大字体与减弱动画。音响仍由伴奏驱动，伙伴反馈先围绕演奏流程。 |
| P2 | 账号与跨设备同步 | 真机验证 Supabase Magic Link 回跳、会话恢复、注销和本地数据保留。再分批同步练习计划、片段和笔记，覆盖 RLS、冲突、删除和失败重试。录音上传单独设计，访客分析继续独立可用。 |
| P3 | 演奏成果反馈 | 在授权曲目和人工标注基准通过后，先探索节奏／音高差异的可解释提示，再评估视频 cover。 |

先复用现有 Windows 和公网网关收集内测数据，沿用每月 100 元以内预算。IP 素材和实体手机样本等待期间，可先做长曲计时、保音高评测与账号本地回归。

## 每轮交付

记录改动、验收样本和测试环境。通过相关 Flutter 测试、静态分析与 Android 回归后，构建普通 APK，并同步代码、已通过的验证和待验收项到 [GuitarPal 开发 PR](https://github.com/jnysw/GuitarPal/pull/1)。
