# GuitarPal 后续开发计划

更新：2026-11-03。以下是下一阶段的执行顺序与验收条件，完成情况以 [演奏空间进度](performance_space/progress.md) 和 [AI 音频进度](ai_audio/progress.md) 为准。

## 已有基础

Android 本地视频练习已接入统一进度、0.01 倍速、A-B 循环、片段和笔记；和弦／分轨结合当前视频，提供滚动和弦、多指法、动态逐轨混音、条件续传与离线缓存。算法端已部署采样时间映射，旧结果保留人工校准。舞台可复用伴奏、用真实 PCM 电平驱动音响、录制纯麦克风演奏、保存草稿与历史，以及双录音 A/B 回听。

这些是 Android 开发版能力，不代表已完成真实歌曲质量基准、手机耳机延迟或公开服务的生产验收。

## 执行顺序

| 顺序 | 目标 | 交付与验收 |
| --- | --- | --- |
| 接入补充，本轮完成 | MelPal 公网内测 | 默认公网地址、个人凭据安全存储、上传／轮询／下载认证、401 暂停与恢复、旧任务与缓存保留；有效令牌真实推理待安全配置后联调 |
| 1，已完成 | 演奏成果关联计划 | 已保存演奏可关联／更换／移除同曲计划；片段计划校验实际区间；计划成果可回听与管理；再次保存录音设置不丢关联；不复制音频、不重复计时、不自动完成计划 |
| 2 | 本地数字音频作品 | 先明确时间映射、导出格式及响度／削顶规则，再把麦克风与冻结伴奏离线渲染；保留原文件；进度、取消、空间不足和失败重试可验证；用户明确导出后再打开系统分享 |
| 3，素材到位后 | IP 舞台互动 | 接入用户 IP 的待机、倒计时、演奏、暂停、结束和重试状态；测试缺素材回退、横竖屏适配、减弱动画与关闭反馈；不输出未经分析的能力评分 |
| 4 | 实际歌曲与设备校准 | 建立有权使用的歌曲样本和人工边界标注；分别测起点映射、和弦切换边界、长曲分轨耗时、重传与音画同步；用有线／USB／蓝牙设备测延迟，保留可解释的人工覆盖 |
| 5 | 账号与上线准备 | 真机 Magic Link 回跳和会话恢复；按需补 Google Provider；随后 Supabase 元数据同步、RLS、冲突／删除墓碑、失败退避与跨设备验收；录音上传另行显式设计 |
| 6 | 进一步的成果反馈 | 在质量基准成立后探索节奏／音高辅助分析与视频 cover；先展示能可靠解释的差异，再考虑评分 |

IP 素材未到位时，继续数字音频、真实歌曲验证及账号工作。测试阶段复用现有 Windows 公网内测服务（个人令牌），旧任务保留 Tailscale 通道；本计划不创建付费资源，沿用用户每月 100 元以下预算约束。

## 每轮交付

完成一项可用功能后，更新开发记录，执行相应领域／界面测试和必要的 Android 原生链路，重新构建普通 APK，将代码与验证结果同步 GitHub 开发分支。保持 Draft PR，避免把模拟器、合成音频或协议检查当作真机听感与音乐准确率结论。

## 已完成：计划成果页面

演奏回听保存后 →「关联／管理练习计划」→ 选择同曲整曲／符合区间的片段计划 → 显式保存。计划 → 成果录音 → 同一条舞台演奏 → 原有回听或关联管理。旧练习成果和新舞台成果保留原种类及原文件；计划关联只用于归档。

数字混音导出是下一项，实施约定见 [导出计划](performance_space/digital_export_plan.md)；本轮未开放导出按钮。公网变更详情见 [接入说明](ai_audio/melpal_public_access.md)。

本轮公网入口：「我的 → 算法服务」保存个人凭据 → 验证连接 → 返回原视频分析。有效令牌联调仍待安全配置，不把个人内测令牌视为正式产品账号。
