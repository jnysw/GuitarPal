# 演奏成果关联练习计划

2026-11-02，Android 本机功能，沿用 Drift v14，不新增音频副本或数据库迁移。

## 使用路径

舞台录制 → 演奏回听 → 保存演奏 →「关联／管理练习计划」→ 选择同曲计划 → 保存关联。已经保存的演奏可从歌曲详情／舞台的演奏录音列表重新打开。标题或试听设置尚未保存时，先保存调整再关联。

计划列表 → 成果录音会在同一条时间线显示旧练习成果与新舞台演奏。舞台成果可打开原有「回听与伴奏」，也能进入关联管理。页面还提供「同曲舞台演奏录音」入口，回到历史录音及 A/B 对比。进入其它播放页前停止旧播放器、清除顺序回听并取消轮询，返回保持暂停。

## 关联语义

- 一条舞台演奏只关联一个计划；更换关联更新同一条记录，移除关联保留原始 M4A、伴奏快照和演奏历史。
- 使用 `performanceTake` 原种类和现有 `planId/segmentId`，不转换成旧 `planOutcome`，防止演奏历史或伴奏回听丢失。
- 只接受同曲计划。片段计划还要求实际录制原曲区间位于该片段内；不对应的选项显示原因并禁用，整曲计划不要求录完整曲。录音无可确认区间、草稿、试录或身份不一致时不关联。
- 关联只做成果归档，不补练习时长／循环、不创建会话、不自动完成计划。计划删除后保留历史 planId 快照，界面说明计划已删除，仍可移除或更换关联；不删除音频。
- 录音文件和关联留在本机，不新增 Supabase 音频上传或同步 outbox。

## 工程与可靠性

`PerformancePlanLinks.setPlan` 在 SQLite 事务中重新读取录音、计划和片段，校验后仅写关联列。选择后目标删除或边界改变时按最新状态拒绝；失败保留原关联，可以重试。重复关联不新增行。

演奏保存通过 `PerformanceTakeRecordingWriter` 能力接口，Drift 在同一事务中插入新录音或只更新已有演奏的标题和回听快照，保留较新的计划／片段、会话、复盘与原始信息。普通旧录音的保存流程不变；备用仓库保留既有记录字段。
