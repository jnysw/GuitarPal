# 演奏空间开发规划

版本：2026-10-31 / v1。当前 P0a 伴奏准备首版已实现（Android Debug），包括歌曲／练习入口、已有分轨选轨、准备／试听与独立方案保存；详见 [实际进度](progress.md)。P0b 舞台、IP 动画与 P0c 演奏录音仍按下列里程碑开发，尚无数据库迁移。用户 IP 素材后续提供。

## 1. 产品定位与闭环

用户把已经练过的歌曲带上舞台，使用自己的伴奏完成一次 cover，保存演奏并听见自己的变化。首版先服务个人演奏，不依赖公开发布、社交广场或算法评分。

核心闭环：选择练习歌曲 → 准备伴奏 → 耳机／录音检查 → 倒计时上台 → 完成一遍 → IP 庆祝 → 回听和保存 → 可选关联计划成果。

建议区分两种方式：

- 自由演奏：不申请录音权限，开伴奏即可演奏；可以开启和弦提示、调慢速度、选择片段，不打断用户。
- 录一遍：明确点击后申请麦克风权限、倒计时、同步开始伴奏与录音；结束后先试听，再保存／重录。默认录音私有、不自动上传。

「检验练习效果」首版通过完整演奏与历史回听达成，不把录音完成率或演奏时长包装成音准／节奏准确率。

## 2. 页面与导航

首版保留现有底部五个入口（今日、练习库、新建、计划、我的），不给它再加第六项。演奏空间有独立的二级页面和沉浸舞台，从当前歌曲自然进入；将来使用频率明确后再决定是否升级为一级入口。

| 页面 | 主要内容 | 进入／离开 |
| --- | --- | --- |
| 演奏准备 | 已选歌曲、整曲／片段、伴奏方案、音量、是否录音、已下载状态 | 歌曲详情「去演奏」、练习页「去演奏」、计划完成卡；返回原位置 |
| 乐队舞台 | 中央 IP 舞台、左右音响、和弦跟练、进度、播放／暂停、录音状态 | 准备完成后进入；返回先处理未保存录音 |
| 演奏回顾 | 本次原始录音、伴奏开关与配比、重录／保存、历史同曲录音、正向反馈 | 录制结束进入；明确保存后再关联计划成果 |

准备路由已实现：`/performance/prepare?sourceId=…`；当前通过已有结果选择区间。`segmentId/planId`、`/performance/stage/:sessionId`、`/performance/review/:takeId` 仍为后续方案。只接受来源 ID 和库内资源引用，不把绝对文件路径塞到路由参数。

进入演奏前暂停并完成上一练习的 recorder 检查点，两个页面不能各自播放或同时计时。演奏暂停不计有效时长；回顾试听也不再次累计一遍练习。演奏来源、片段、计划均沿用原 ID。

## 3. 舞台布局与 IP 留位

```text
┌ 返回       歌曲名 · 伴奏方案       演奏设置 ┐
│      C    Am    F    G  → 随播放滚动       │
│                                          │
│  左音响       中央 IP / 乐队舞台    右音响 │
│   ◉ ◉           IP 素材留位          ◉ ◉  │
│                灯光 / 地台               │
│                                          │
│      倒计时 / 演奏中 / 已完成             │
├ 时间 ─────── 播放进度 ─────────── 总时长 ┤
│         播放 / 暂停     结束录制          │
└──────────────────────────────────────────┘
```

竖屏把舞台放在中间，伴奏与录音控制固定底部，音轨详情收进弹层；横屏扩展地台及音响间距。中央留位按相对区域布局，不按某一张未来图片尺寸写死。安全区、返回键、麦克风状态始终可见。

IP 首批接入静态 PNG／WebP 与少量状态即可：待机、倒计时准备、演奏陪伴、暂停等待、完成庆祝、鼓励重试。具体姿态、台词、形象比例与声音等素材到位再定；资源缺失时使用无人物的舞台占位，不能把未提供素材的角色当成正式 IP。

拟议 `StageCharacter` 只消费语义事件：`ready / countdown / started / paused / resumed / takeFinished / retry / recordingError`，绘制与音频业务解耦。未来按用户 IP 实际格式决定静态序列帧、Rive 或 Lottie，不预先引入多套渲染依赖。

完成一遍后可触发简短庆祝／掌声／一句鼓励，可关闭或减少动效；鼓励基于真实事件，例如「这次完整弹完了」「又留下了一次演奏」，不说未经分析的「节奏很准」「超过了多少用户」。首版使用本地文案和素材，不需要在线大模型对话。

## 4. 伴奏：按清单静音，不删除音频

默认推荐「吉他由我演奏」：复用已有分轨任务和本机缓存，将算法实际返回的吉他轨静音，播放其余独立模型轨。这里“删去”表示在该伴奏预设里静音／不加入混音，保留原文件、原任务和练习页混音偏好，方便恢复及切换乐器。

- 只使用真实清单中的 ID／来源／名称。算法只有一条 `guitar` 就显示吉他，不虚构主音／节奏；若未来确实返回多个吉他轨，让用户确认要去除哪几条。
- 首版提供「吉他由我演奏」「关闭人声」「自定义混音」三个可用方案，只有实际返回相应轨道时才启用对应预设。关闭人声与去吉他可组合。
- 不把派生 `instrumental` 与其来源模型轨同时播放。已有合成伴奏仍含吉他时，不能把它宣传成“去吉他伴奏”。没有独立吉他轨就明确提示暂不支持精确去吉他，可自定义可用轨，或显式重新分轨。
- 自动优先匹配当前源文件修订及区间的既有结果，缺文件时只下载需要的轨，复用已有条件续传与校验缓存。下载失败不重复推理，不自动上传原曲。开始录制前先把所需文件准备完整，不能录到一半等待下载。
- 首次开始可以只做 A-B／练习片段的舞台演奏。若仅有片段分轨，限制舞台在该区间，不把片段伴奏装作整曲。整曲伴奏需要整曲结果。
- 分离会有残留串音，UI 不承诺原吉他完全消失。目标轨调到 0 只保证不主动混入该轨，不保证其他轨没有吉他残留。

拟议 `BackingPreset`：`sourceRevision + taskId + range + includedStemIds + gains/mutes/pans + masterVolume + speed`。独立于 `VideoMixSelection` 保存，进舞台不会覆盖原练习设置。所有播放轨使用同一混音引擎及媒体时钟，不给每轨创建独立播放器。

## 5. 两侧音响动画

音响外壳保持稳定，主要让振膜轻微缩放、光晕明暗变化；不让整台音响大幅抖动，不用随机动画冒充伴奏能量，也不从 BPM 猜测敲击。

首选在原生实际混音后的 PCM、应用逐轨静音／增益／声像与主音量之后提取左右声道 RMS／peak，返回带源媒体时间的轻量 envelope。Dart 接收约 15–20 Hz，动画插值到显示帧率，attack／release 平滑；峰值削顶只做电平提示，不放大其它轨。用轻量事件流传输聚合值，不跨通道传整块 PCM；每包带会话 generation 和媒体时间戳，丢弃上一场演出的旧事件。

- 吉他静音、独奏或主音量变化后，动画必须反映实际输出。左右声道相同则两个音响同动，不伪造立体声差异。RMS 表示应用数字音频能量，不代表物理声压；另监听系统音量／静音，系统输出归零时视觉静止。
- 暂停、静音、缓冲、结束与后台时衰减回静止；seek 丢弃旧时间戳包，避免回跳后仍播旧动画。耳机播放也可保留舞台视觉，系统减弱动画时仅显示静态灯或细小电平。
- 当前 `AlgorithmMixPlatform.snapshot` 没有电平字段；这属于待做的原生增量。可先用音频离线包络校验渲染，但准确混音驱动以真实输出 envelope 为准；调试占位必须标注，不当作已实现。

## 6. 录制与回听

当前已有练习录音／计划成果录音、试听和原曲对比，可复用权限、设备私有存储、列表与保存流程。但不能把「伴奏外放后由麦克风收到」当成数字混音。

第一阶段先提供「耳机伴奏 + 纯麦克风原始录音」：推荐用耳机并提供试录／输入检查；保存可复现的伴奏预设、源区间、实际速度、录音开始相对伴奏的偏移、设备／路由与已确认延迟。伴奏本机回听时与麦克风轨分别可调，麦克风原始文件始终保留。

后续才开发可导出的「麦克风 + 数字伴奏」混音和视频 cover：统一时间基准、采样率、通道数与延迟补偿，导出以同一 preset 和 offset 离线渲染。当前录音接口不暴露采样级启动时间，不能声称现有 MediaRecorder 与 AudioTrack 已逐样本同步。需先测量有线／USB／蓝牙耳机延迟与系统音频处理，并支持试听对齐；未经验证不默认开实时人声监听，避免反馈啸叫与蓝牙延迟困扰。

录音会话状态机：`preparing → ready → countdown → performing ↔ paused → review → saved/discarded`，错误／后台／中断分支显式处理。首版“录一遍”暂停时结束当前 take 或要求用户确认重录，不把多个不连续片段拼成假装一镜到底的作品；自由演奏可正常暂停。开始前检查磁盘、音频焦点、权限、输入可用性、伴奏完整性；结束先可靠保存临时文件，用户决定保存或丢弃，退出有未保存提示。

## 7. 数据与工程复用

| 现有能力 | 复用方式／需要补足 |
| --- | --- |
| 来源／片段／计划 | 原 ID 与 source revision、原媒体毫秒坐标 |
| AlgorithmStemStore | 只取所需缓存、续传、校验、本机解码 |
| AlgorithmMixPlatform / 原生 AudioTrack | 共享 seek／倍速／混音，补实际输出电平与播放时钟事件 |
| PracticeRecording / 录音平台 | 权限／私有文件／回听；补演奏用途、伴奏预设引用和同步数据 |
| recorder／计划成果 | 一次演奏只写一个会话；成果仅显式关联，重复保存幂等 |
| 离线指法与滚动和弦带 | 舞台显示开关，随同一媒体时钟运行 |

建议新增 `features/performance/{domain,application,data,presentation}`，先在领域层定义会话状态、伴奏预设、IP 事件、节奏包络，再接 UI。候选实体：`PerformanceSession`、`BackingPreset`、`PerformanceTake`（引用现有录音并保存 mix／同步快照）。当前 `PracticeRecordingKind` 仅 segmentTake／planOutcome，不能直接假装已有 performanceTake；正式实现时设计向后兼容迁移，不覆写旧种类。只同步允许的元数据，录音文件上传／分享以后显式触发。

IP 资源候选描述：`assetId/version`、舞台归一化 anchor／safeBounds、各状态资源映射、过渡规则和 reducedMotion fallback。素材后续到位即可按契约适配，不影响伴奏与录音核心。

## 8. 有序开发与验收

| 批次 | 交付 | 验收重点 |
| --- | --- | --- |
| P0a 伴奏闭环 | 歌曲入口、准备页、实际清单去吉他／去人声、自定义／缓存准备 | 不删源文件；缺轨、片段／整曲、派生去重、断线恢复、旧设置隔离 |
| P0b 舞台首版 | 中央 IP 留位、两侧音响、同一媒体时钟、自由演奏、和弦显示 | 进入／返回不重复播放和计时；实际混音电平驱动；暂停／静音／后台／seek 动画正确 |
| P0c 演奏成果 | 耳机试录、倒计时、纯麦克风 take、对齐回听、保存／重录、同曲历史 | 音频路由与中断、文件恢复、延迟可解释、成果幂等、未保存保护 |
| P1 IP 接入 | 使用用户素材适配状态、庆祝与可关闭反馈 | 资源缺失 fallback、减弱动态、状态事件不乱触发；无虚构音乐评分 |
| P1 数字作品 | 数字伴奏／麦克风导出混音、封面／成就卡、本地分享 | 时间／音量一致、原始文件保留、用户明确导出与分享 |
| P2 深化 | 视频 cover、历史对比、节奏／音高辅助分析 | 有评测和质量基准后才开放分数；标明分析能力边界 |

P0a／P0b 不需要等 IP 原画，也不需要新租模型服务器，优先复用已有结果与本机能力。上线前另验收现有私网算法入口的生产鉴权／可达性；本方案不把当前 Debug 服务当作已可公开上线的后端。

## 9. 建议增加的情绪价值设计

1. **小型首演**：先练过的一小段也能上台，降低必须弹完整曲的压力；完成片段就给真实的完成反馈。
2. **这一版比上一版**：同一首歌并列播放两次演奏，保留用户自己的「这次更稳了」标记，先让人听见进步，再考虑算法。
3. **我的乐队席位**：选择自己担任吉他／贝斯／人声等角色，对应静音实际轨道；只对算法支持的乐器开放。
4. **轻量演出纪念**：保存日期、歌曲、演奏片段和用户寄语的本地成果卡。掌声、IP 互动、动效都可关闭，不虚构观众或点赞数。
5. **练习与演奏各有所用**：练习页负责拆解和循环，舞台默认收起技术面板，突出完整表达；和弦／指法提示按需显示，熟练后可关闭。

后续 IP 交付只需说明形象、可用状态／动作及素材格式，再补台词与互动偏好；现在无需为此阻塞伴奏和舞台基础开发。
