## P0a：伴奏准备首版

已实现 Android Debug 入口：本地歌曲详情「去演奏 · 准备伴奏」，以及练习页右上角耳机按钮。进入前原视频暂停并保存检查点；返回不自动播放。准备页不创建第二条练习会话，伴奏试听不计时。

准备页按当前源文件元信息、提取区间、任务类型／终态及结果时长筛选已有分轨，支持选择已有整曲或片段。歌曲或结果变化时拒绝载入／播放／保存；不自动发起分析或上传。没有有效结果时引导返回练习页完成分轨。

- 默认「吉他由我演奏」只保留其余独立模型轨，关闭人声可组合。无独立吉他／人声轨时不伪造对应预设。自定义选择沿用模型／派生轨去重规则，至少保留一条轨。
- 只准备所选音轨，完整缓存免下载；缺文件复用已有 GET 下载、条件断点续传与校验。服务器结果过期时可用完整缓存，缺失轨不请求过期服务器；需要更多轨道时明确返回练习页重新分析。
- 本机 WAV／FLAC 解码后进入同一个 AudioTrack，支持试听／暂停／定位、0.01 倍速、总音量、逐轨音量／静音／独奏／声像。新动态配置接口接受实际清单 ID，不受旧七轨配置限制。
- 保存到独立 `performance_backings/<sourceId>.json`，包括任务／输入／清单指纹、原视频区间、所选轨控制、主音量和速度。串行原子写入，兼容校验失败时重设；不改练习页混音方案，不写旧音轨练习偏好。
- 改选结果或选轨会停止旧试听；暂停下载、关闭页面或进入后台保留缓存并停止声音。后台回来须重新准备，可复用完整缓存。取消中的准备先收尾再接新请求，迟到的解码／下载不接管新选择。
- 删除歌曲会清理伴奏方案；清理失败不撤销已成功的歌曲删除，排队保存不能复活已删方案。没有数据库迁移，当前 Drift 仍 v13。

P0a 可以准备、试听和保存伴奏；P0b 舞台进度见下。演奏录音／成果、计划完成卡入口属于后续阶段。准备页选择的是已分析的区间，不会将片段分轨当成整曲，也不提供未经分析的任意裁剪。

## P0b：自由演奏舞台

准备页新增「进入演奏舞台」：先保存已应用方案、关闭试听，再进入舞台载入完整本机缓存；不会自动播放或自动下载。伴奏的实际区间、速度与混音控制沿用保存方案。来源／任务／清单变化或缺文件时引导返回准备页，不能悄悄重新分轨。

中央保留无人物的伙伴席位，根据准备／演奏／暂停／完成状态展示中性图标和文案。两侧音响的振膜与光晕使用实际混音后左右 RMS／peak；音量／静音／独奏／声像在原生 PCM 合成后反映。硬件播放头选取当前帧块，20 Hz 聚合事件带 generation 与 seek epoch，避免播放缓冲或上次载入的电平误驱动。系统音量归零、暂停、后台与结束时静止；设置可关闭动效，系统减弱动画同样生效。没有模拟人物、鼓励音频或成绩评分。

- 明确开始后才计时；准备、试听、暂停、后台和 seek 跳过的歌曲时间不计入。一个舞台实例拥有一个 recorder，重播沿用同一 ID；每 5 秒保存检查点，结束／返回保存最终记录，失败可重试或明确直接退出。
- 原练习 recorder 在进入准备页前暂停；舞台生成一条独立演奏练习记录。返回准备／原视频后都不自动播放，也不会覆盖原练习混音偏好。当前没有将演奏记录归入某个计划或分析区间对应的练习片段，以免误关联；未新增数据库种类。
- 支持播放／暂停、进度定位、从头演奏、自然结束和总音量设置。离开前释放同一全局混音引擎；切后台／被其它完整页面覆盖时暂停释放，回来需要再次明确开始，保持原位置与本场音量，不覆盖保存方案。
- 有同源、同修订且区间重叠的已完成和弦结果时显示滚动和弦提示，使用原视频绝对时钟与已有人工校准；紧凑布局隐藏，设置可关闭。横屏矮视口可滚动，320px 与双倍文字使用紧凑舞台；控制不依赖未来 IP 图片尺寸。

P0b 交付时尚未实现麦克风录制与回听，其后续进展见下方 P0c。正式 IP、数字合成导出和计划完成卡入口仍待后续。

## P0c：原始录音与本机对齐回听首版

舞台新增「麦克风试录」「录一遍」，并在舞台顶部和本地歌曲详情提供「演奏录音」。先推荐耳机并明确开始，再检查麦克风权限与至少 64 MB 可用空间，三秒倒计时后录制；试录不播放伴奏、约三秒自动结束。正式演奏从已选择伴奏区间的开头开始，冻结本次实际速度、主音量和逐轨控制。录音期间锁定自由跳转、重播和设置；结束后可回听、保存或丢弃。

- 保留纯麦克风 AAC/M4A，不把伴奏外放串音当数字混音。快照记录来源修订、分析输入／清单指纹、原视频区间、实际伴奏配置、时间及设备列表。起点来自原生单调时钟下录音启动确认与混音硬件播放头的估计，设备／编码延迟尚未校准；可用设备列表不代表已验证的实际路由。
- 回听加载录制时快照所选的完整缓存，不重新推理或下载。录音／伴奏分别调音量，伴奏可开关；±2 秒／10ms 步进手动试听对齐并保存。两条本机播放器按原速度映射并做 200ms 容差的粗粒度纠偏，不声称逐样本同步，暂不导出合成文件。原视频／分轨变化或缺失时仍可听原始录音。
- 一个正式 take 中途暂停、伴奏停止、设备列表变化或切后台就结束并保留，不自动接着录。权限弹窗的短暂 inactive 不取消前台授权流程，真正 paused／hidden 仍取消待启动请求。原生 `onStop` 对新演奏种类提交可用录音，旧练习录音仍沿用原取消语义。
- 原子草稿日志先于麦克风启动保存，已提交但未保存的 M4A 可恢复；退出明确保留草稿，下次从同曲历史回听／保存／丢弃。突然进程终止、文件尚未封装完成的 `.pending.m4a` 无法保证恢复，界面明确提示。最终保存同 ID 幂等；数据库失败保留草稿与原文件，已保存成果不能被草稿丢弃操作删除。结束草稿的旧排队写入不能复活记录。
- Drift 从 v13 升到 v14：录音表新增 nullable 快照字段及新的演奏种类，旧片段／计划成果记录不改写。已保存记录、标题、回听音量与对齐设置可重开；本次舞台仍只有一个计时 recorder，试录、倒计时、回听不计时，不自动完成歌曲或计划。
- 同曲历史按日期显示已保存演奏与未保存草稿，分别回听、调整、重命名保存和删除。此阶段还未做两条历史录音并排对比或计划完成卡关联。

## 音响动效可见性与和弦对齐补充

音响的来源是伴奏的实际混音输出，麦克风试录和原始录音都不驱动舞台音响。此前仅在 RMS 变化时缩放，持续音会停在一个大小且小电平变化不明显。现在将真实电平按 -60..0 dBFS 映射为可视强度，增加电平条及低幅振膜载波；持续音下振膜仍移动，能量归零则停止，不随机生成音量或从 BPM 猜能量。关闭动效／系统减弱动画时保持静态，界面显示来源、静音及电平未收到的原因。

Android 用实际合成恒定正弦伴奏检查五帧振膜缩放差超过 1%，再验证暂停／静音归零及既有录音／回听计时。正常页、全屏与舞台的和弦都复用新的自动采样映射；旧结果仍保留人工校准，Windows 更新步骤见 [说明](../ai_audio/CHORD_TIMELINE_UPDATE.md)。本批 Flutter 449 项、安卓新链路 2 项通过，未进行新的线上推理。
