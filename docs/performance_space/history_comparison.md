# 同曲演奏 A/B 回听

2026-11-02，Android 本机功能。入口：歌曲详情或舞台 → 演奏录音 → 对比两次演奏 → 选择两条已保存成果 → 开始对比。A 为较早录制，B 为较晚录制；草稿须先回听并保存。

两张卡展示标题、日期、实际录制倍速与时长。点击 A／B 会保留原曲对应位置；播放中切换继续回听，暂停中切换保持暂停。进度条使用两次演奏的共同原曲区间，到共同末尾停止，再点播放从共同起点开始。只使用一个原生录音播放器，不并播两条录音，不加载伴奏或联网，不写入练习会话。

沿用每次录制的快照与已保存试听微调，坐标公式与单条回听一致：

```text
sourceMs = preset.startMs + (micMs - leadMs + alignmentMs) * preset.speed
micMs = (sourceMs - preset.startMs) / preset.speed + leadMs - alignmentMs
```

共同区间同时受原始录音长度、实际结束位置和伴奏区间约束，不拉伸录音来凑齐时长。不同倍速保留各自原来的录制速度；切换时按原曲位置对应，不自动变速。相同来源 ID 但源文件路径／大小／修改时间不同、起点估计缺失、共同区间短于一秒、文件丢失或快照身份不一致时不开放错误的对应播放，用户仍可返回逐条回听。

这是基于已有起点估计的本机听感对比，不是声学自动对齐。耳机与编码延迟、演奏起拍差异仍可能存在；先从单条回听调整并保存后，再进入对比。当前不归一化响度，不生成评分，不改写录音文件，不保存临时回听音量。后台／页面覆盖立即停止，回到前台需明确播放；待完成的旧播放请求不能在后台重启。

实现：`PerformanceComparison` 负责来源及时间映射，`PerformanceComparisonController` 串行使用既有麦克风播放器，`performanceComparisonProvider` 仅按库内 ID 读取已保存成果。没有数据库迁移、录音上传或新的算法任务。
