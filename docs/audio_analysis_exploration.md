# GuitarPal 音频分析探索

更新日期：2026-10-15

## 当前已接入的实验能力

练习详情中的普通试录和计划成果时间线都提供“音频分析（实验）”入口。分析完全在 Android 设备本地完成：原生层通过 `MediaExtractor` 与 `MediaCodec` 把 GuitarPal 私有目录中的 AAC/M4A 录音解码为 PCM，再把压缩后的结果返回 Flutter。原始 PCM 不写入文件，也不会上传。

当前 `energy-onset-v1` 输出：

- 最多 120 个点的响度波形概览；
- 平均响度与峰值电平（dBFS）；
- 低于 -45 dBFS 的窗口占比；
- 基于短时能量突增检测到的起音数量；
- 样本充分时，相邻起音的中位间隔和间隔变异系数。

界面不会给出总分、进步百分比或“弹得准/不准”的结论。起音间隔波动只描述这条录音内部的时间一致性，不能证明它与原曲拍点一致；可识别起音不足时明确显示“样本不足”。

## 当前限制

- 能量起音容易受环境噪声、扬声器串音、延音、和弦扫弦与失真效果影响。
- 当前尚未分析参考原曲，因此不能判断抢拍、拖拍或节拍偏移。
- B站 WebView 不提供稳定、合规的原始音轨访问能力，现阶段只分析用户自己的录音。
- 当前结果按需计算，没有写入数据库；算法变化后不会读取过期缓存。
- 音高、和弦正确性和复音分离尚未实现。

## 后续顺序

1. **本地视频参考节奏**：只对 GuitarPal 管理的本地视频，在用户录音保存的 `referenceStart` / `referenceEnd` 区间解码参考音轨，分别提取起音序列。
2. **时间对齐**：先校正录音开始延迟，再比较最近拍点偏差，展示偏早/偏晚分布和置信度；无法可靠匹配时不给结论。
3. **单音音高轨迹**：针对干净单音场景验证自相关或 YIN，展示音高轨迹及有效帧比例，不直接用于和弦或失真音色。
4. **结果缓存**：指标稳定后再引入 `RecordingAnalysis`，通过 `recordingId + algorithmVersion` 保存，支持算法升级后重新计算。
5. **真实样本评估**：使用不同手机、距离、耳机/扬声器、木吉他/电吉他和噪声环境建立测试集，公开适用范围与失败条件。

## 验证要求

- M4A 解码和分析不得阻塞 Android 主线程。
- 所有数值必须经过 Flutter 边界校验，波形限定在 0–1，比例限定在 0–1。
- 删除录音后不能继续读取对应分析数据。
- 模拟器集成测试覆盖真实录制、提交、解码分析、播放、跳转、暂停和文件删除。
